
# 🚀 Документация API бэкенда (XramBot) для Telegram Web App

## 🔐 1. Авторизация и безопасность

Все API-запросы от Web App к бэкенду должны быть авторизованы.

* **Механизм**: Frontend должен передавать данные авторизации (обычно это валидированная строка `initData` от Telegram или сгенерированный на её основе токен).
* **Валидация**: Бэкенд извлекает `telegramId` пользователя из токена. Если этот ID не совпадает с параметром `telegramId` в самом запросе, сервер вернет `403 Forbidden`.

## 🧾 2. Суть и механика работы "Чеков" (Подарочных ваучеров)

Система позволяет покупать товары (Premium, Звезды, TON) не для конкретного человека сразу, а в виде **Чека**.

**Как это работает:**

1. Пользователь в Web App выбирает товар и жмет "Создать чек".
2. Frontend отправляет запрос на создание транзакции, но в параметр `targetUsername` передает не реальный юзернейм, а специальный системный флаг срока действия:
* `cheque_1` — чек действителен 1 час.
* `cheque_24` — чек действителен 24 часа.
* `cheque_inf` — бессрочный чек.


3. Бэкенд распознает этот префикс, ставит транзакции флаг `IsCheque = true` и вычисляет `ChequeExpiresAt`.
4. Товар физически **не выдается** в момент оплаты. Вместо этого средства резервируются, а пользователю выдается ссылка вида: `https://t.me/BotName?start=chk_{TransactionId}`.
5. Любой другой пользователь, перешедший по этой ссылке в боте, становится `ActivatorTelegramId`. Бэкенд мгновенно проверяет срок действия и зачисляет зарезервированный товар на аккаунт этого нового пользователя.

## 🛒 3. Создание заказов (Endpoints)

Все запросы на создание заказов — это `GET` запросы. Они **создают заявку** (переводя её в статус `Pending`) и возвращают реквизиты или ID для дальнейшего отслеживания.

### Базовые параметры (нужны везде):

* `telegramId` (long): ID текущего пользователя.
* `currency` (string): Валюта оплаты (`TON`, `USDT`, `RUB`, `Stars`).
* `method` (string): Способ оплаты (`InternalWallet`, `CryptoTransfer`, `BankCard`, `TelegramStars`).

### 3.1 Покупка Telegram Premium

`GET /api/transactions/create/premium`

* **Специфичные параметры:**
* `months` (int): 3, 6 или 12.
* `targetUsername` (string): `@username` получателя ИЛИ параметр чека (`cheque_inf`).



### 3.2 Покупка Telegram Stars

`GET /api/transactions/create/stars`

* **Специфичные параметры:**
* `stars` (int): Количество звезд (минимум 50).
* `targetUsername` (string): `@username` получателя ИЛИ параметр чека (`cheque_24`).



### 3.3 Покупка NFT-подарка

`GET /api/transactions/create/gift`

* **Специфичные параметры:**
* `giftId` (string): Нормализованный ID подарка (строго без дефисов!).
* `targetUsername` (string): `@username` получателя.



### 3.4 Пополнение внутреннего кошелька

`GET /api/transactions/create/topup`

* **Специфичные параметры:**
* `amount` (decimal): Сумма пополнения (например, `1.5` TON).



### 3.5 Вывод средств с кошелька

`GET /api/transactions/create/withdrawal`

* **Специфичные параметры:**
* `amount` (decimal): Сумма вывода.
* `targetAddress` (string): Адрес TON-кошелька пользователя (`EQ...` или `UQ...`).



### 3.6 Аренда NFT-подарка

*(Примечание для бэкендера: этот эндпоинт нужно добавить в `TransactionApiFunctions.cs` по аналогии с остальными, так как метод в `TransactionManager` уже готов)*
`GET /api/transactions/create/rent`

* **Специфичные параметры:**
* `nftAddress` (string): Блокчейн-адрес конкретной модели.
* `nftName` (string): Имя для отображения в UI.
* `days` (int): Количество дней аренды.
* `totalAmountTon` (decimal): Общая стоимость аренды за выбранный срок.

## 🔁 4. Жизненный цикл и флоу оплаты (Для Frontend)

**Формат успешного ответа при создании заказа:**

```json
{
  "Success": true,
  "TransactionId": "d3b07384-d9a... (Guid)",
  "PaymentCode": "TX-A1B2C3D4",
  "TargetUsername": "username или null",
  "Amount": 150.5,
  "AmountUsd": 2.50,
  "Currency": "TON",
  "PaymentMethod": "CryptoTransfer"
}

```

### Как Web App должен вести пользователя после получения этого ответа:

* **Если `PaymentMethod == InternalWallet**`: Web App должен просто показать экран загрузки и начать опрашивать статус по `TransactionId`. Если на балансе есть деньги, бэкенд спишет их и статус сменится на `Completed`.
* **Если `PaymentMethod == CryptoTransfer**`: Web App должен отобразить системный TON-адрес проекта, QR-код и сумму. Обязательно попросить пользователя указать `PaymentCode` (`TX-...`) в комментарии к переводу. Заявка сгорит через 20 минут.
* **Если `PaymentMethod == TelegramStars**`: Оплата звездами обрабатывается только через бота (метод `SendInvoice`), поэтому Web App должен показать кнопку "Вернуться в бота для оплаты" или инициировать закрытие окна.

## 📡 5. Отслеживание и управление

### 5.1 Получение статуса (Polling)

`GET /api/transactions/{id}`

* Frontend должен вызывать этот метод раз в 3-5 секунд, чтобы узнать, прошла ли оплата.
* Ответ содержит объект `Transaction` с полем `Status`.

### 5.2 Кнопка "Я оплатил" (Принудительная проверка)

`POST /api/transactions/{id}/check`

* Используется, если пользователь перевел крипту и хочет ускорить проверку. Бэкенд проверит блокчейн или базу на наличие изменений.

### 5.3 Отмена транзакции

`POST /api/transactions/{id}/cancel`

* Вызывается, если пользователь нажал "Отменить" или закрыл окно оплаты в Web App. Переводит статус в `Cancelled`.

## 📘 6. Справочник статусов (`TransactionStatus`)

* `Pending` — заказ создан, система ждет поступления денег (или подтверждения смарт-контрактом). Автоматически перейдет в Cancelled через 20 минут.
* `Processing` — деньги получены, идет процесс отправки товара в блокчейне/через Fragment.
* `Completed` — товар успешно доставлен пользователю (или чек успешно сгенерирован).
* `Failed` — деньги списаны, но при выдаче произошла ошибка (например, NFT уже забрали). Средства возвращаются на баланс внутреннего кошелька.
* `Cancelled` — заказ отменен (пользователем или по истечению времени).
